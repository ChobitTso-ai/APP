## 1. 範圍決定(2026-09-16)

原始 handoff 的核心是「CBCT 不用截圖就能變成期刊圖」,需要 Cornerstone3D、
TypeScript + Vite 建置流程,以及 DICOM 去識別化工作流。

**這個範圍已經縮減。實際要做的是:**

> 把 FigureLab 中文化、加上牙科範本,放進 App 中心給科內使用。

| 項目 | 狀態 |
|---|---|
| 中文化介面 | ✅ 要做 |
| 牙科／根管病例範本 | ✅ 要做 |
| 併入 App 中心 | ✅ 要做 |
| 安全的本機儲存 | ✅ 要做(見 §3 M1) |
| DICOM / CBCT 檢視 | ❌ **不做** |
| Cornerstone3D | ❌ **不做** |
| TypeScript + Vite 建置 | ❌ **不做** |
| MPR / 體積渲染 | ❌ **不做** |

### 這個決定帶來的直接好處

**維持單一 HTML 檔,就不需要建置步驟** —— 於是 DentFigure 可以直接住在
`apps/dentfigure/`,與 case-marker、pdf-toolbox 等四支工具完全一致:

- `pages.yml` 不必改。合併到 main 後約一分鐘全站上線,跟現在一樣。
- DentFigure 出問題時,**不會連帶讓其他工具無法部署** —— 這是先前考慮獨立 repo
  的唯一實質理由,現在不存在了。
- `app.js` 的 `slugOf()` 正則 `/^apps\/([^/]+)\//` 直接比中,**瀏覽次數與 🆕 徽章
  免費可用,首頁程式一行都不必改。**
- 登入守衛沿用既有寫法(`location.replace('../../')`),不需要絕對路徑。

### 什麼情況才需要重新考慮

單一檔案目前 19,088 行。若日後真的要做 DICOM,或檔案成長到難以維護,再回頭
評估建置流程與獨立 repo。**在那之前,不要為了架構純度而付出部署耦合的代價。**

## 3. 階段

### M0 — 基線與法務(*= Assignment 001*,本次 PR)

### M1 — 安全的本機儲存

**排在中文化之前,因為這是唯一「不需要使用者做任何動作」就會發生的暴露。**

現況(見 `ARCHITECTURE_CURRENT.md` §13 第 7b 項):三層儲存全部預設寫入病患影像,
其中兩層寫死沒有選項。自動存檔每次變動後 2.5 秒、每 30 秒、關頁面前各寫一次到
`localStorage`,而 `localStorage` 關掉瀏覽器不會清。診間共用電腦上,下一位使用者
會看到「↺ Recover unsaved session?」,按下去就是前一位病患的影像。

要做三件事:

1. **下載存檔預設改為 lightweight**(只存設定,不含像素)。要 bundled 必須明確
   勾選,並跳警告說明「這個檔案本身含有病患影像」。
2. **自動存檔改為分頁關閉即清除。** 接受的代價:瀏覽器當掉後跨重啟救回的能力
   會失去。以共用電腦的情境判斷,這個交換划算。
3. **加上明顯的「結束並清除本機資料」按鈕**,搭配常駐顯示「本機目前存有 N 張
   影像」。具名專案要繼續能用(一個病例不會一次做完),重點不是禁止儲存,
   而是讓殘留看得見、一鍵清得掉。

同時處理兩項較小的:

4. **停止序列化原始檔名**,改存中性別名。檔名是最常見的 PHI 外洩路徑。
5. **關閉 Gemini 生成路徑。** 上游的 AI 生成會把影像位元組上傳到 Google
   (`figure_lab.html:16186`, `:16217`)。這個範圍不需要 AI 生成,直接移除入口
   比做資產分類閘門簡單且安全。

> 這些都是**刻意偏離上游**。上游預設 bundled 對它的使用者(做細胞影像的實驗室
> 研究者)完全合理,裝置殘留沒有病患風險。每項都要有自己的回歸測試,而且
> **不應該當成 bug 回報給上游。**

完成條件:共用電腦上關閉分頁後,不留下任何可還原的病患影像;下載的存檔預設
不含像素;沒有任何路徑會把影像送出這台機器。

### M2 — 中文化與牙科範本(*= Assignment 002*)

1. **介面中文化。** 全站文字轉繁體中文,與 App 中心其他工具一致。
   保留上游頁尾署名與 Zenodo 引用(見 `../NOTICE.md`)。
2. **牙科範本。** 只定義版面與建議的面板角色,**不得注入病患資料或臨床結論**:
   - 根管治療病例(術前 PA → 工作長度 → 充填後 → 追蹤)
   - 根尖手術
   - 牙齒移植
   - 牙外傷
   - 一般縱向追蹤
3. **臨床影像匯入預設值** —— 口內照、PA、環口的常見尺寸與方向。
4. **隱私檢查表**(一般影像用,非 DICOM):提醒檢查可見識別資訊、提供遮蔽、
   匯出前要求確認。
5. **併入 App 中心**:
   - 建立 `apps/dentfigure/index.html`,`<head>` 最前面加登入守衛
   - 在 `app.js` 的 `APPS` 加卡片,`url: 'apps/dentfigure/index.html'`,
     `group: 'desktop'`
   - 更新根目錄 `README.md` 檔案結構
   - 版本號與 `updated` 依 `CLAUDE.md` 慣例處理

完成條件:科內同仁能用繁體中文介面,從 PNG/JPG/TIFF 做出一份完整的根管病例圖,
不需要 PowerPoint。

## 4. 測試策略

上游 469 筆測試是安全網。原則:**絕不因為「畫面看起來正常」就接受一次重構。**
圖表幾何是精密工作。

| 層 | 內容 |
|---|---|
| **上游回歸** | 469 筆,不修改,對釘選快照執行,只要行為仍是繼承來的 |
| **中文化回歸** | 上游 `encoding.spec.js` 會檢查 CP1252 mojibake、UTF-8 BOM、無效 UTF-8。**中文化會大量新增非 ASCII 字元,這組測試因此變得更重要,不是更不重要。** |
| **隱私回歸** | 關閉分頁後 `localStorage` 不得殘留影像資料;下載的預設存檔不得含 base64 像素 |
| **網路誠實性** | 核心流程若發出非預期的網路請求就失敗。基線目前已符合,**趁還沒加任何東西先鎖住** |
| **範本測試** | 每個牙科範本能套用、能匯出、不注入任何資料 |

App 中心既有的 `./tests/run.sh` 與這組是分開的,互不影響。

## 5. CI

`.github/workflows/dentfigure-upstream.yml` 執行釘選的上游測試,並以 `paths:`
限定只在 `apps/dentfigure/**` 變動時觸發 —— 否則每次改首頁或其他工具都要多等
3.4 分鐘。

**CI 不會改變任何執行期行為** —— app 從不載入 workflow 檔案,因此符合
Assignment 001「不得有功能性改動」的要求。

基線是在 Chromium build 1194 上以 override config 跑出來的(容器缺少 Playwright
1.60 需要的 build)。CI 會自行安裝瀏覽器,跑的是上游那一套。**若 CI 的數字與 469
不同,以 CI 為準。**

## 6. 風險

| 風險 | 緩解 |
|---|---|
| 中文化破壞 UTF-8 編碼(上游踩過:PowerShell 一次雙重編碼 519 個破折號) | `encoding.spec.js` 每次都跑;**絕不用 PowerShell 編輯這些檔案** |

| 中文化後與上游差異過大,無法再套用上游修正 | 保留釘選快照可 diff;優先移植匯出與完整性相關的修正 |

| 41 個 CC-BY 圖示的署名在匯出時遺失 | 任何能帶圖示的匯出路徑都要帶著它的署名 |
