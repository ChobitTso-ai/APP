# 即時投票後端設定步驟（Google 試算表 + Apps Script）

「即時投票」App 的題目與作答結果，存在**你自己的 Google 試算表**裡。
以下步驟做一次就好，約 5 分鐘。跟當初設定「使用統計」是同一套流程。

> **Google Apps Script 是什麼？**
> 它就是 Google 自己的服務（`script.google.com`），跟 Gmail、Google 試算表同一個帳號、
> 同一套權限。你可以把它想成「掛在你 Google 帳號底下的一小段程式」，
> 它有權限讀寫你的試算表，也能對外開一個網址讓網頁呼叫。
> **免費、不用信用卡、資料全部留在你自己的 Google Drive**，不經過任何第三方。

```
題目與作答結果  →  你的 Google 試算表
收票的那段程式  →  你的 Google Apps Script
網站本身        →  GitHub Pages（App 中心本來就在這，不會變）
```

---

## ⚠️ 先看這一段：這個工具能放什麼、不能放什麼

來作答的人（學員、與會同仁）**沒有** App 中心的 NCKUH / ENDO 帳密，
所以觀眾作答頁 `join.html` **刻意不加登入保護**——加了就沒人投得下去。

這代表：**6 位數的 PIN 就是唯一的門檻。**

| ✅ 適合 | ❌ 不要用 |
| --- | --- |
| 教學問答、晨會小測驗 | 病患個資、病歷相關 |
| 課程回饋、滿意度調查 | 人事案、考績、敏感投票 |
| 科務討論的意見調查 | 任何外流會出事的內容 |
| 現場即時提問收集 | 正式考核計分（見下方說明） |

另外兩點：

- **正確答案不會傳到觀眾的手機。** 評分是在 Apps Script（伺服器端）做的，
  看網頁原始碼也偷不到答案。
- **但「答得快加分」只是趣味性質。** 因為是各自作答、沒有統一倒數，
  作答時間是手機自己回報的。**不要拿這個工具當正式考核。**

看結果與改題目一律要「管理碼」，光有 PIN 看不到結果。

## 步驟 1：建立試算表

1. 開 https://sheets.google.com → 建立**空白試算表**
2. 檔案名稱改成好認的，例如 `投票結果`

> 要跟「App 中心統計」用**不同的試算表**（也可以同一個，但分開比較好整理）。

## 步驟 2：貼上程式碼

1. 在試算表上方選單點 **擴充功能 → Apps Script**
2. 會開一個新分頁，裡面有預設的 `function myFunction() {}` ——**全部刪掉**
3. 把 [`docs/voting-backend.gs`](voting-backend.gs) 的**全部內容**複製貼上
4. 按上方 💾 儲存（專案名稱隨便取，例如 `投票後端`）
5. （可選）在上方函式下拉選單選 `setup` 按 ▶ 執行一次，
   會先建好三個工作表、也順便確認授權沒問題

## 步驟 3：部署成網頁應用程式

1. 右上角點 **部署 → 新增部署作業**
2. 左邊齒輪 ⚙️ **選取類型 → 網頁應用程式**
3. 設定三個欄位：
   - **說明**：隨便填，例如 `v1`
   - **執行身分**：**我**（你自己的帳號）
   - **具有存取權的使用者**：**任何人** ← ⚠️ 這個要選「任何人」，
     不是「任何擁有 Google 帳戶的人」。來投票的人沒登入 Google 也要能作答。
4. 按 **部署**
5. 第一次會跳授權：**授權存取 → 選你的 Google 帳號 →**
   出現「Google 尚未驗證這個應用程式」時，點左下 **進階 → 前往「投票後端」（不安全）**
   → **允許**。（這是你自己寫的腳本存取你自己的試算表，正常現象。）
6. 部署完成後會顯示一個**網頁應用程式網址**，長得像：
   ```
   https://script.google.com/macros/s/AKfycb.....................《很長》.../exec
   ```
   **按「複製」，把這串網址貼回對話給 Claude。**

## 步驟 4：Claude 接上前端

把網址給 Claude 後，Claude 會填進 `apps/live-poll/api.js` 最上方的 `POLL_ENDPOINT`，
推上 PR 合併後就能正式使用。

> **想先自己測？** 主持端右上角有「⚙ 後端設定」，可以暫時填入網址試跑。
> 但那只存在你這台電腦，**觀眾掃 QR 會連不上**——正式上線還是要填進程式碼。

## 怎麼用

### 主持人（電腦）

1. App 中心 → **🗳️ 即時投票**
2. **📝 編輯題目**：填標題 → 選設定 → 用下面的按鈕新增題目
   - 題型：單選 / 是非 / 多選 / 評分量表（1–5）/ 開放文字
   - 設定：匿名或記名、一支手機能不能重複投、要不要計分、送出後能不能看結果
3. 按 **🚀 建立投票** → 產生 **PIN** 與 **QR Code**
4. **📣 開放投票** 分頁投影出去，大家掃碼作答
5. **📊 結果** 分頁看即時長條圖；**🖥 投影模式**可以放大投影（←→ 換題）
6. 結束後按 **🔒 結束並封存**，結果會寫進試算表的「結果彙總」

### 參加的人（手機）

掃 QR 直接進，或到作答頁輸入 6 位數 PIN。作答完按送出就結束了，不用註冊、不用登入。

### 換一台電腦要看舊結果

**📚 我的投票** → 輸入 **PIN ＋ 管理碼** → 取回結果。
（資料一直都在你的 Google 試算表裡，換電腦不會不見。）

## 試算表裡有什麼

打開試算表會看到三個工作表：

| 工作表 | 內容 |
| --- | --- |
| **投票** | 每一場一列：PIN／建立時間／標題／狀態／管理碼／回覆人數／設定與題目 |
| **作答紀錄** | 每人每題一列：時間／PIN／裝置代號／暱稱／題號／題目／答案／正確／得分 |
| **結果彙總** | 按「結束並封存」時寫入的人類可讀結果（含排行榜） |

- **匿名場次的「暱稱」欄會是「（匿名）」**，不會存任何名字。
- 「裝置代號」是瀏覽器自己產生的隨機字串，用來防止同一支手機重複投票，
  **認不出是誰**，也跟 Google 帳號無關。

## 容量與人數

後端用 Google 的免費額度，實務上的限制是**每天 90 分鐘的程式執行時間**。

- 這個 App 設計成**觀眾只寫不讀**（作答時不會一直向後端要資料），
  所以 50 人 × 10 題的一場會議，大概只用掉每日額度的 **1% 不到**。
- **建議 50 人以內**。真的要開到上百人，Apps Script 就不是對的工具了，
  那時要換別的後端（另外討論）。

## 更新後端程式碼（改版時）

`docs/voting-backend.gs` 之後若有更新，照這樣套用：

1. 試算表 → **擴充功能 → Apps Script**
2. 把編輯器內容**全選刪掉**，貼上新版 `voting-backend.gs`，儲存 💾
3. **部署 → 管理部署作業** → 右上角 ✏️ 鉛筆 →
   **版本**選「**新版本**」→ **部署**
   （⚠️ 只存檔不重新部署的話，線上跑的還是舊版）
4. 改完可以在函式下拉選單選 `clearCache` 執行一次，把舊的暫存清掉

**網址不會變**，所以前端不用跟著改。

## 疑難排解

| 狀況 | 處理 |
| --- | --- |
| 主持端顯示「還沒設定投票後端」 | `api.js` 的 `POLL_ENDPOINT` 還沒填，或暫時設定被清掉了 |
| 觀眾說「連不上」但主持人自己測沒問題 | 你用的是「⚙ 後端設定」的暫時網址——要把網址填進程式碼才對外生效 |
| 出現「連不上投票後端」 | 部署時「具有存取權的使用者」要選**任何人**；改完程式一定要建**新版本**重新部署 |
| 「找不到這組 PIN」 | PIN 打錯，或那場投票的那一列被從試算表刪掉了 |
| 「管理碼不正確」 | 管理碼是 6 碼英數（沒有 0/O/1/I，不分大小寫），在「📣 開放投票」分頁看得到 |
| 結果數字沒動 | 「📊 結果」分頁的「自動更新」每 5 秒抓一次；也可以按「🔄 重新整理」 |
| 手動改過試算表之後數字怪怪的 | 在 Apps Script 執行一次 `clearCache` |
| 想清掉舊場次 | 直接在「投票」工作表刪掉那一列即可（作答紀錄可另外自行整理） |
