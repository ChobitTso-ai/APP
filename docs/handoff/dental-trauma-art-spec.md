## 全域規格

每一張都要遵守：

| 項目 | 規格 |
|---|---|
| 格式 | 獨立 `.svg` 檔，一個項目一個檔。不要外部參照、不要 `<image>`、不要 base64 |
| viewBox | 單顆牙 `0 0 360 560`／多顆牙 `0 0 720 560`／單一物件小圖 `0 0 240 240`／App 圖示 `0 0 1024 1024` |
| 背景 | 透明，不要畫背景矩形。**唯一例外是 `icon-master.svg`**，它要深色圓角底 |
| **文字** | **整份 SVG 不可出現 `<text>` 元素**，不要任何文字、字母、數字標註 |
| 樣式寫法 | 用 inline 的 `fill=`／`stroke=` 屬性。不要 `<style>` 區塊、不要 CSS class |
| 解剖層次標記 | 用 **`data-part` 屬性**，值為 `enamel` `dentin` `pulp` `pdl` `bone` `gingiva` `lesion` `arrow`。**不要用 `id`** |
| 檔案大小 | 每個檔案 < 60KB |
| 視角 | 上顎中門齒的唇舌向剖面（labio-lingual cross-section），要看得到牙釉質／牙本質／牙髓腔與根管／牙周韌帶／齒槽骨／牙齦 |

三個規格的理由，請務必遵守：

- **不可有文字**：App 要中英文切換，標籤由 HTML 渲染。圖上有字就得畫兩套。
- **不可用 CSS class**：多張圖會被 inline 進同一個頁面，class 會互相汙染。
- **用 `data-part` 不用 `id`**：`id` 在同一份文件裡必須唯一。`fx-root-thirds.svg`
  一個檔裡就有三顆牙、三套 enamel／dentin，用 `id` 當場撞號；十六張圖 inline
  進同一頁更是全毀。`data-part` 可以重複，`querySelectorAll('[data-part="enamel"]')`
  一樣抓得到，互動 highlight 不受影響。

多顆牙的圖，每顆牙包一層 `<g data-tooth="1">`（2、3 依此類推），
裡面才是各構造的 `data-part`。這樣 App 可以只亮其中一顆。

寫法範例：

```xml
<g data-tooth="1">
  <path data-part="bone"    d="…" fill="#A89478" stroke="#87755C"/>
  <path data-part="dentin"  d="…" fill="#E9C98C" stroke="#C9A360"/>
  <path data-part="enamel"  d="…" fill="#F4F7FA" stroke="#C9D4E2"/>
  <path data-part="pulp"    d="…" fill="#E4575F" stroke="#B83A44"/>
  <path data-part="lesion"  d="…" fill="none" stroke="#FF4D4F" stroke-width="4"/>
</g>
```

## 母版一致性的範圍與例外

先完成 `01 base-closed-apex.svg` 當母版。這些圖在 App 裡會並排比較，
外形不一致就失去診斷鑑別的意義——**但一致性不能凌駕解剖正確性**。
兩者的界線如下。

### 一律沿用母版，不得重畫

- **牙冠外形**（切端、近遠中輪廓、齒頸線）——所有單顆牙的圖（01–08、11–17）都一樣。
- **齒槽骨與牙齦的整體輪廓與位置**——除非該診斷本身就是骨或牙齦的傷害。
- **畫面構圖**：牙齒在 viewBox 中的基準位置、縮放比例、線寬。

### 必須依解剖重畫，不受一致性約束

| 圖 | 可以改什麼 |
|---|---|
| 02 未成熟根 | **牙根與根管重畫**：較短、管壁薄、平行或外張、根尖喇叭狀開口。牙冠必須與 01 完全相同。齒槽骨高度可隨較短的牙根調整 |
| 09 根折／10 齒槽骨骨折 | 多顆牙構圖，牙齒本體沿用母版，骨與牙齦依骨折線重畫 |
| 13 外突性脫位／14 側向脫位／15 內縮性脫位 | 見下節「位移圖的畫法」 |
| 16 脫落 | 齒槽窩空置並填入血凝塊；牙齒整顆移出、可任意角度；牙根表面加點狀質感 |
| 所有傷害本身 | `lesion`（折裂線、缺損）、受傷的 `pdl`／`gingiva`／`bone` 一律依診斷重畫 |

### 位移圖的畫法（13／14／15）

**牙齒本體（`enamel`／`dentin`／`pulp`）的 path 不要重畫**，整組包一層 `<g>`
用 `transform` 移動。這樣外形保證一致，位移量也一眼看得出來。

| 圖 | transform | 周邊組織 |
|---|---|---|
| 13 外突性脫位 | `translate(0,-45)` 左右（向切端方向），數值可微調到視覺明確 | 根尖側露出空的齒槽窩；`pdl` 拉長並部分撕裂；齦緣被牽起 |
| 14 側向脫位 | 以齒頸部為支點 `rotate(15, cx, cy)` 左右，牙冠向舌側、根尖向唇側 | 唇側骨板在根尖處畫出穿孔缺口；根尖側 `pdl` 撕裂、對側受壓變窄 |
| 15 內縮性脫位 | `translate(0,30)` 左右（向根尖方向），牙冠切端明顯低於母版 | 根尖周圍 `pdl` 層**中斷不畫**（韌帶腔消失）；根尖處骨質壓縮 |

角度與位移量是建議值，以**視覺上明確可辨**為準，可自行微調；
但三張圖的牙齒 path 必須完全相同，只有 `transform` 與周邊組織不同。

### 為什麼 18、19 要拆成小圖

原本是兩張 960×280 的橫幅。拆開的理由有三個：

1. **沒有文字就分不出容器**。HBSS 瓶和生理食鹽水瓶畫出來長得差不多，
   靠圖形硬分辨只會讓醫師猜。拆成獨立小圖之後，App 會在每張圖下面渲染
   中英文標籤（HBSS 平衡鹽溶液／牛奶／生理食鹽水／唾液／自來水 ✗），
   辨識交給文字，圖只負責「一眼認得出是個容器」。
2. **秒數與分鐘畫不出來**。「沖 10 秒」「60 分鐘內」用圖形表達不可能精確，
   硬畫只會誤導。這些數字一律由 HTML 圖說負責，圖上不出現任何數字。
3. **手機上看不清**。960×280 的五格橫幅塞進手機寬度，每格剩不到 70px。
   拆開後 App 可以在手機排成 2×2 或直向單欄，電腦排成一列。
