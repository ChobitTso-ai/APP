# 縮網址後端設定步驟（跟首頁統計共用同一個試算表）

縮網址**不用另外開試算表**：它跟首頁的「使用統計」是同一支 Google Apps Script、
同一個試算表、同一個部署網址。你只要把統計試算表裡的程式**換成新版**一次，約 3 分鐘。

```
首頁造訪次數＋短網址清單與點擊次數  →  你原本的「App 中心統計」試算表
                                       （多出「短網址」「點擊紀錄」兩個工作表）
程式                                →  同一支 Apps Script（docs/stats-backend.gs）
網站本身                            →  GitHub Pages（不會變）
```

> 為什麼不會互相干擾：首頁統計的請求不帶 `action` 參數、縮網址的一定帶，程式看這個分流。
> 統計的三個工作表（總覽／每日／stats）完全不動。

短網址長這樣：

```
https://chobittso-ai.github.io/APP/s/?rct
```

> 網址的長度受限於 GitHub Pages 的網域（`chobittso-ai.github.io/APP`）。
> 想要 `xx.tw/rct` 這種更短的，要另外買網域綁到 GitHub Pages，屬於另一件事。

---

## ⚠️ 先看這一段：兩道門

| | 誰能做 | 要什麼 |
| --- | --- | --- |
| **點短網址**（轉址頁 `s/`） | 任何人 | 什麼都不用，**刻意不加登入**（同事用手機相機掃 QR，開的是沒登入過的瀏覽器） |
| **建立／修改／刪除／看清單**（App 中心的「縮網址」） | 有「建立金鑰」的人 | App 中心登入 **＋** 建立金鑰 |

**為什麼要另外一組金鑰？** App 中心的 NCKUH / ENDO 帳密寫在公開的網頁原始碼裡，等於公開的。
如果只靠它，任何人都能用 `chobittso-ai.github.io/APP/s/…` 這個看起來像本科的網址，
轉到釣魚網站。建立金鑰存在 Apps Script 的「指令碼屬性」裡，**不在程式碼、不進 repo**，
只分享給要建立短網址的同事。

另外：

- **短網址任何拿到的人都點得開**——不要把病患資料放進目標網址或標題。
- 點擊紀錄只記「時間＋代號」，**不記是誰點的**（Apps Script 本來也拿不到點擊者的 IP）。
- 只接受 `http://`、`https://` 的目標網址。

---

## 步驟 1：打開統計試算表的程式

1. 打開你原本的 **「App 中心統計」試算表**（當初照 `docs/STATS_SETUP.md` 建的那個）
2. 上方選單 **擴充功能 → Apps Script**

## 步驟 2：換成新版程式

1. 編輯器裡原本的程式**全選刪掉**
2. 把 [`docs/stats-backend.gs`](stats-backend.gs) 的**全部內容**複製貼上
   （新版＝原本的統計程式＋下半部的「縮網址」區塊）
3. 按上方 💾 儲存

## 步驟 3：執行 setupShortlink，拿到建立金鑰（這步不能省）

1. 上方的函式下拉選單選 **`setupShortlink`** → 按 **▶ 執行**
2. 若跳出授權：**審查權限 → 選你的 Google 帳號 →**
   「Google 尚未驗證這個應用程式」時點左下 **進階 → 前往（不安全）→ 允許**。
   （你自己的腳本存取你自己的試算表，正常現象。）
3. 下方「**執行記錄**」會出現一行：
   ```
   建立金鑰：abcd-2345　（請記下來，分享給要建立短網址的同事）
   ```
   **把這組金鑰記下來。** 試算表裡會多出「短網址」「點擊紀錄」兩個工作表。

> 不想用自動產生的？到左側 ⚙️ **專案設定 → 指令碼屬性**，把 `ADMIN_KEY` 改成你要的字串即可。

## 步驟 4：重新部署（⚠️ 只存檔沒用）

1. 右上角 **部署 → 管理部署作業**
2. 右上角 ✏️ 鉛筆 → **版本** 選「**新版本**」→ **部署**

**網址不會變**，所以不用把網址給 Claude，前端也已經接好了。
（建立金鑰**不用**給 Claude，也不要貼進 repo。）

## 步驟 5：試用

1. App 中心 → **縮網址** → 輸入建立金鑰（只要第一次）
2. 貼一個網址、按「建立短網址」
3. 用手機相機掃畫面上的 QR code，應該會直接開到目標網址
4. 回到縮網址頁按「🔄 重新整理」，那一筆的點擊次數會變成 1

## 怎麼用

| 想做的事 | 怎麼做 |
| --- | --- |
| 建立短網址 | 貼上目標網址；代號可以自訂（例如 `rct-2026`），留空自動產生 5 碼 |
| 拿 QR code | 建立後直接顯示；清單每一筆的「🔳 QR」可下載 PNG（下方可加標題與網址，方便印）、SVG（印刷放大不糊），或複製圖片直接貼到 LINE／簡報 |
| 改連到哪 | 清單的「✏️ 編輯」改目標網址——**已經印出去的 QR code 也會跟著改**，代號不能改 |
| 看點擊次數 | 清單上每一筆都有總次數、近 7 天、最後點擊時間；可依「點擊最多」排序 |
| 預覽目的地 | 在短網址最後加 `+`（例如 `…/s/?rct+`）只顯示目的地、不跳轉、不計次 |
| 直接在試算表加 | 在「短網址」工作表新增一列，填**代號**與**目標網址**兩欄就能用（其他欄可空白） |
| 刪除 | 清單的「🗑 刪除」——短網址與 QR code 立刻失效；「點擊紀錄」工作表的歷史保留 |

### 試算表裡有什麼

| 工作表 | 內容 |
| --- | --- |
| **短網址** | 每個短網址一列：代號／目標網址／標題／建立者／建立時間／更新時間／點擊次數／最後點擊 |
| **點擊紀錄** | 每點一次一列：時間／代號。想看「哪天點最多」可以用樞紐分析表 |

## 金鑰管理

| 狀況 | 在 Apps Script 執行 |
| --- | --- |
| 忘記金鑰 | `showShortlinkKey`（顯示在執行記錄） |
| 金鑰外流、同事離職 | `resetShortlinkKey`（換一組新的，舊的立刻失效；大家下次開縮網址頁會被要求重新輸入） |

金鑰連續輸錯 30 次，15 分鐘內會全部擋下（防亂猜）。

---

## 容量

跟首頁統計共用 Google 的免費額度。科內日常使用（每天數十到數百次點擊）應該碰不到上限，
但**確切配額以 Google 官方的「Apps Script 配額」說明為準**（這裡沒有實測過上限）。

速度：每次點短網址都要問一次 Apps Script，通常 1～3 秒；隔一陣子沒人用時
（Apps Script 冷啟動）會更久，轉址頁會顯示「正在前往目的地…」，超過 3 秒會提示稍候。
這是用免費後端的代價——要做到瞬間跳轉得換付費的轉址服務或自己的伺服器。

## 更新後端程式碼（改版時）

1. 試算表 → **擴充功能 → Apps Script**
2. 把編輯器內容**全選刪掉**，貼上新版 `stats-backend.gs`，儲存 💾
3. **部署 → 管理部署作業** → 右上角 ✏️ 鉛筆 → **版本**選「**新版本**」→ **部署**
   （⚠️ 只存檔不重新部署的話，線上跑的還是舊版）

**網址不會變，金鑰也不會變**（存在指令碼屬性，不在程式碼裡）。首頁統計會一起更新，數字不會歸零（存在試算表裡）。

## 疑難排解

| 狀況 | 處理 |
| --- | --- |
| 縮網址頁顯示「統計試算表的程式還沒更新」 | 步驟 2 的程式沒換，或換了沒做步驟 4「新版本」重新部署 |
| 轉址頁顯示「縮網址服務尚未啟用」 | 同上 |
| 「後端還沒設定建立金鑰」 | 步驟 3 的 `setupShortlink` 沒執行 |
| 「金鑰不正確」 | 執行 `showShortlinkKey` 看目前的金鑰；可能有人執行過 `resetShortlinkKey` |
| 「連不上縮網址後端」 | 網路問題；或部署的「具有存取權的使用者」不是**任何人**（首頁統計當初已設好，通常不會遇到） |
| 點短網址出現「找不到這個短網址」 | 代號打錯，或那一列被刪了 |
| 手動在試算表加的代號 `007` 變成 `7` | 那格被當成數字了：選取整欄 → 格式 → 數值 → **純文字**，再重打一次（setupShortlink 建立的工作表已預設純文字） |
